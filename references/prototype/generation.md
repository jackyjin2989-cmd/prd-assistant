# 原型生成

交付表达产品行为的最小 HTML 原型，不伪造生产能力。是否生成、交付哪些产物、材料冲突和未知项如何处理，统一遵循 [SKILL.md](../../SKILL.md)；本文件只定义实现要求。仅原型任务不附加 PRD，不默认双端或额外业务交互。

## 输入与范围

- 按 [input-intake.md](../input-intake.md) 处理文字、截图和设计稿；现状截图不自动成为未来需求。已确认需求与有效硬约束优先，通用惯例只补不影响业务的呈现细节。
- 列出本次确认的平台、页面、状态及主流程；核心缺失或冲突按入口处理，不靠补造规则完成原型。
- 第三方或来源不明材料只用于获准的结构、层级与组件模式参考，不复制受限制资产、源码或大段文案。不访问业务网站补材料。
- 图文不一致时依 [图片指南的图文一致性](../图片嵌入与截图指南.md#图文一致性) 判断修正方向，不用原型现状倒改已确认需求。

## 生成流程

1. 确认范围与目标材料，记录必要假设和未覆盖项。
2. 先形成下节还原规格，再实现页面骨架、关键组件和视觉令牌；不直接套无关模板。
3. 用语义控件实现最小主流程、输入校验及可见状态反馈；不以单个提示框替代实际状态变化。
4. 按目标端做内容重排，遵循 [responsive-guide.md](responsive-guide.md)，不整体缩放或擅自替换业务操作。
5. 检查资源、数据和可访问性底线；状态就绪协议按 [screenshot-tooling.md](screenshot-tooling.md) 实现，不另设固定等待。
6. 按 [visual-validation.md](visual-validation.md) 决定实际验证或降级；不能截图不阻止交付 HTML，但不得虚报验证完成。

## 截图驱动还原

编码前内部记录以下规格；只对决定骨架或关键交互的未知项追问：

| 项目 | 记录内容 |
|---|---|
| 页面身份 | 产品类型、端类型、可见设计特征；证据不足时不猜组件库名称 |
| 页面骨架 | 顶栏、侧栏、标签页、筛选区、内容区、分页、浮层的顺序、比例与定位模型 |
| 组件规格 | 按钮层级、输入框、表格行列、表单标签、抽屉和操作列的形态 |
| 视觉令牌 | 颜色、字号、字重、行高、间距、圆角、边框与阴影；用 CSS 变量统一 |
| 内容与状态 | 可辨识且获准使用的文案、选中项、状态、行数与密度；不可见行为不作事实 |
| 目标视口 | CSS 宽高、DPR、参考图片像素与裁切范围；未知值单独标注，不能由图片像素直接推定 |

还原顺序为页面身份与骨架 → 几何与密度 → 组件形态 → 排版与颜色 → 装饰细节。目标是高密度表格界面时，不默认改成大卡片、强圆角或大留白；未经确认不改版。优先用可信、可离线交付的通用实现，按目标调整样式，同时保留原生控件的语义和键盘行为；库名相同不代表视觉一致。

## HTML 最低要求

- 默认单个 HTML，内联必要 CSS/JS；提供 `<!doctype html>`、匹配正文的 `lang`、`<meta charset="utf-8">` 和 `<meta name="viewport" content="width=device-width, initial-scale=1">`。不禁用用户缩放或限制最大缩放。
- 按内容使用 `header/nav/main/section/form/button` 等语义元素；用真实按钮和链接，不把仅能点击的普通元素当等价替代。
- 表单提供可见标签及明确关联（`label` 与控件 `id`，或包裹关联）；图标按钮有可访问名称，必要状态同步到 ARIA。
- 保持合理的 Tab/Shift+Tab 顺序、可见且不被遮挡的焦点、Enter/Space 激活；模态打开后移入焦点并限制在模态内，关闭后回到有效触发位置。非模态浮层不套用模态焦点规则。
- 错误提示说明原因并关联控件（如 `aria-describedby`），错误态同步 `aria-invalid`；动态结果使用合适的状态通知，不只靠颜色。不要用占位文本替代标签。
- 保持文字可读和缩放后内容可达；普通文本对比度以 4.5:1、大文本以 3:1 为检查基线（大文本指至少 18pt，或粗体至少 14pt；标志、装饰及不可用控件等例外另判）。这不是完整无障碍认证；触控建议见响应式指南，真实检查见视觉验证指南。
- 不将凭据、内部地址、真实个人数据或敏感查询值写入 HTML、状态入口、浏览器存储、截图及记录。

## 状态与交互

- 关键状态优先从交付 HTML 的真实控件或已有路由进入，校验操作前后可见结果、选中值、业务状态和 ARIA 一致。
- 为复现展示状态可提供明确的无敏感值查询入口，例如实际实现了空态入口才记录 `?state=empty`。这是呈现入口示例，不是完整命令；查询直达状态不证明用户主流程能到达。
- 不通过只改 class、解除禁用、直接改内部状态或临时注入脚本，伪装真实交互已通过。模拟数据和模拟提交应明确，不连接真实业务接口。
- 截图前状态标识、异步完成与字体等就绪条件只按执行契约维护；交付说明中的状态入口与图片引用按图片指南记录，不默认创建额外索引或测试章节。

## 浮层交互

先确定模态／非模态、嵌套层级及关闭预期，再处理事件，不套通用补丁。

- 面板重渲染可能移除事件目标，使冒泡阶段的祖先判断失准。优先保持稳定面板边界，结合事件发生时的 `composedPath()`、触发器与浮层关系判断内外点击；先核对 capture、pointerdown、click 的实际监听阶段。
- `stopPropagation()` 只在确认事件模型且不破坏委托时局部使用，不能作为所有浮层的首行修法。
- 互斥浮层按需求互斥，嵌套浮层保留必要父层；Escape 通常关闭当前最上层可关闭浮层并恢复焦点，不一律关闭全部。
- 实测时覆盖连续选择、外部点击、键盘、嵌套、关闭后重开及焦点返回；未执行就标为未验证。几何边界的判据见视觉验证指南。

## 资源与数据边界

- **自包含**描述打包方式；**离线可用**描述无外部资源时核心功能仍可运行；**不主动外连**描述页面的资源与请求行为，三者不能互相代替。
- 默认使用内联或随包可信资源与模拟数据，不加载远程字体、脚本、图片，不主动请求外部接口。静态检查资源 URL、CSS 引用、fetch/XHR/WebSocket/beacon、表单提交、跳转及持久化行为；不执行来源不明代码来检查它。
- 确需外部资源时先确认来源、必要性、授权和离线替代，再决定是否采用；不能以资源例外绕过不访问业务网站的边界。缺少授权继续用本地替代，不自动下载或安装。
- 本地文件或无头模式不保证断网。宿主或模型如何处理已提供材料，取决于当前工具的数据边界与授权，不因 HTML 自包含就承诺数据不出机；截图隔离与零外连证据见执行契约。

## 交付与完成

交付请求的 HTML 和必要说明；已知限制、待确认项及未验证状态有才写。结构、真实交互、视觉、资源检查分别如实报告，不以一张截图或静态检查代替其他检查。完成应覆盖已确认范围、核心流程和可操作控件；未修复的已知问题按视觉验证指南记为未完成，不包装成能力受限。
