# PRD 示例

以下均为自创虚构场景，不复制竞品文本。每例先给输入，再给完整预期输出或明确标注的片段；数值、状态和默认值只在该例设定内有效。它们是写作示范，不是独立模型已运行的记录。

## A：多端同步的局部校验调整

### 输入

> 只写 PRD。H5 和 APP 的批量图片导出页共用规则，本次最少选择数量从 5 张改为 2 张，新增最多 20 张。提示改为“每次选择 2—20 张图片”。0 张或 1 张时沿用原有下限校验位置和行为：选择区下方提示“至少选择 {下限} 张图片”，导出按钮置灰；超过 20 张提示“每次最多导出 20 张图片”，按钮置灰；2—20 张可导出。除阈值与上限反馈外，其余既有校验沿用。已发起的导出任务不受此次数量调整影响。无需验收、原型或背景铺垫。

### 完整输出

```markdown
# 批量图片导出数量调整

## 1. 改动点

1. H5 和 APP 批量图片导出页的选择提示改为“每次选择 2—20 张图片”。
2. 最少选择数量从 5 张改为 2 张，最多 20 张。选中 0 张或 1 张时，沿用原有下限校验位置和行为，选择区下方提示“至少选择 2 张图片”，导出按钮置灰；超过 20 张时提示“每次最多导出 20 张图片”，按钮置灰；2—20 张可导出。其余既有校验沿用。
3. 已发起的导出任务不受此次数量调整影响。
```

仍属 A：只改已有局部规则，两个端同步不构成耦合业务。上下限、可见反馈和继承边界均来自输入。

### 同一输入的反例

错误片段：“为了全面提升体验，目标是把导出成功率提升至 95%；本期不调整水印；另附完整验收矩阵。”

问题：输入没有成功率目标或水印边界，且明确无需验收。删除这些新增内容，不是说所有 A 类都禁止验收；若用户明确要求，应按写法指南简短补充。

## B：单模块内的类型筛选

### 输入

> 只写 PRD。素材库列表当前没有类型筛选，本次新增筛选弹窗。进入页面默认“全部”，显示全类型素材。点击列表右上角“类型”打开弹窗，单选“全部／图片／音频”，回显当前已生效选项；在弹窗中选择不立即影响列表。点“应用”关闭弹窗，按选项筛选列表，并将入口文案改成该选项。点“取消”或右上角关闭，放弃本次选择，保持原列表。列表排序沿用现有规则；重新进入页面重置为“全部”。筛选后无结果时显示“暂无该类型素材”和“清除筛选”，点击后恢复全部素材及“全部”入口。素材数据及现有使用权限不变。不增加 URL 参数持久化、原型或验收章节。

### 完整输出

```markdown
# 素材库类型筛选

## 1. 背景与范围

素材库列表当前没有类型筛选。本次新增“类型”筛选弹窗，不改变素材数据及现有使用权限，不增加 URL 参数持久化。

## 2. 列表与筛选弹窗

进入页面默认“全部”，显示全类型素材；重新进入页面时重置为“全部”。列表排序沿用现有规则。

| 位置或操作 | 规则与结果 |
|---|---|
| 列表右上角“类型”入口 | 点击打开筛选弹窗；应用筛选后，入口文案显示已选项 |
| 弹窗选项 | “全部／图片／音频”单选，回显当前已生效选项；选择时不立即改变列表 |
| 应用 | 关闭弹窗，按选项筛选列表，并更新入口文案 |
| 取消或右上角关闭 | 放弃本次选择，保持原列表及已生效条件 |

## 3. 无结果

筛选后无结果时，显示“暂无该类型素材”和“清除筛选”。点击“清除筛选”恢复全部素材，入口文案恢复“全部”。
```

这里默认值“全部”指生效条件；首屏入口“类型”与应用后入口显示选项的区别来自输入，不擅自统一。适合比较的规则放表格，简单规则用自然段；B 不要求全部表格化。

## C：共享设备与跨角色借用流程

### 输入

> 只写 PRD。设备借用目前线下登记，本次上线申请端与管理员工作台。每张借用单对应一台设备，只由申请人本人在申请端查看和操作；只有设备管理员使用工作台。设备状态为“可借／预留／借出”；借用单状态为“待审核／待领取／借用中／已归还／已取消／已驳回”。
>
> 申请人在可借设备详情点击“申请借用”，不填其他字段。提交成功创建待审核单并把设备设为预留，打开该单详情；申请端“我的借用”和工作台列表都显示此单。若提交时设备已非可借，不创建单，提示“设备已不可借，请选择其他设备”。重复提交同一次申请只返回已有单，不新增单。
>
> 管理员在工作台列表打开待审核单，可“同意”或“驳回”；同意后变为待领取，设备仍预留。驳回必须填写原因，未填写时保持待审核并提示“请填写驳回原因”；提交原因后变已驳回并释放设备为可借，申请端详情显示原因。申请人可在待审核或待领取时取消，单变已取消，设备可借。
>
> 管理员在待领取单点击“确认领取”，单变借用中、设备借出；在借用中单点击“确认归还”，单变已归还、设备可借。其余状态不显示这些操作；申请人在借用中不能取消。状态操作成功后，两端列表和详情都显示最新单状态、设备状态；驳回单详情显示原因。若按旧状态发起操作，保持当前状态，提示“状态已更新，请刷新后操作”。本期不做消息通知。线下历史不导入，只处理上线后通过本流程创建的单据。

### 完整输出

```markdown
# 设备借用线上流程

## 1. 背景与范围

将线下登记改为申请端与管理员工作台协作。申请人仅查看和操作本人的借用单；设备管理员使用工作台。本期不做消息通知。线下历史不导入，只处理上线后通过本流程创建的单据。

## 2. 共同对象与状态

一张借用单对应一台设备。设备状态为“可借／预留／借出”；借用单状态为“待审核／待领取／借用中／已归还／已取消／已驳回”。

| 当前单状态 | 角色与操作 | 单据及设备结果 |
|---|---|---|
| 尚无单据 | 申请人在可借设备详情申请借用 | 创建待审核单，设备变预留 |
| 待审核 | 管理员同意 | 单变待领取，设备仍预留 |
| 待审核 | 管理员填写原因后驳回 | 单变已驳回，设备可借；申请端详情显示原因 |
| 待审核或待领取 | 申请人取消 | 单变已取消，设备可借 |
| 待领取 | 管理员确认领取 | 单变借用中，设备借出 |
| 借用中 | 管理员确认归还 | 单变已归还，设备可借 |

只在表中对应状态展示相应操作，申请人在借用中不能取消。操作成功后，两端列表和详情同步呈现最新单状态及设备状态；驳回单详情显示原因。按旧状态发起操作时，保持当前状态，提示“状态已更新，请刷新后操作”。

## 3. 申请端

在可借设备详情点击“申请借用”，无需填写其他字段。成功后打开新单详情，该单同时出现在“我的借用”和工作台列表。

若提交时设备已非可借，不创建单，提示“设备已不可借，请选择其他设备”。重复提交同一次申请只返回已有单，不新增单。取消入口和结果按共同状态表执行。

## 4. 管理员工作台

从列表进入借用单详情，按共同状态表展示同意、驳回、确认领取或确认归还操作。

驳回必须填写原因；未填写时保持待审核并提示“请填写驳回原因”，不执行驳回。
```

C 的复杂性来自设备占用与借用单、申请人与管理员操作的耦合；共同状态只完整定义一次。无需为了 C 加技术架构、验收矩阵或流程图。

## 保真对照：允许否定，不添加事实

以下每行左列就是该行全部已确认输入，不继承其他案例。右列“错误”用于识别偏差，不是推荐输出。

仅需整理已确认限制时不补计算方案。若任务需要完成结果展示而替代内容或来源决定核心行为，再追问；不能从上面的短句推断答案。

纯语言精简也遵守共同前提：输入“对名称进行校验”可改“校验名称”，但不能补成“名称最多 20 字”。输入只说“给出提示”，不能创造具体报错文案；无信息的“本功能是核心亮点”可以删。

## 未知与冲突示范

### 核心未知

输入：“写删除素材的 PRD，要有删除入口，但谁能删、是否能恢复还未决定。”

完整预期回应：“核心方案待确认：哪些角色可删除素材？删除后是否允许恢复？这两项决定权限和删除结果，确认前不定稿。”

不得自行选管理员权限、回收站期限或永久删除。若交付确定部分，交付说明标为未定稿并说明缺口；未经用户明确暂缓，不把问题塞进 PRD。

### 非核心未知

输入：“标签为空时展示提示区，不阻止保存；提示文案尚未定，只整理这条规则。”

过程中的提问：“标签为空时的提示文案用什么？提示区及不阻止保存的规则已明确，可以先整理。”问题先记入需求记忆，不直接写进 PRD。

用户回复“用‘可填写标签，方便查找’”后，完整输出：“1. 标签为空时展示提示区，文案为‘可填写标签，方便查找’，不阻止保存。”

只有用户回复“文案这项先待确认”时，才可输出：“1. 标签为空时展示提示区，不阻止保存。提示文案：待确认（Q-001，用户已明确暂缓）。”用户不回答不等于选择暂缓。

### 有效硬约束冲突

输入：“现行已确认约束是导出文件不能包含私人联系方式。为了方便，把私人联系方式一并导出；未提供约束变更依据。”

完整预期回应：“核心方案待确认：新要求与仍有效的导出限制冲突。请确认可适用的约束更新依据；确认前不能把导出联系方式写为已采用方案。”

## 只审校与局部修改

### 只审校

输入：“只审校，不改文件。草稿第 2 节写‘名称必填’，第 4 节写‘名称为空也可保存’；没有优先口径。”

完整预期输出：“结论：核心方案待确认。位置：第 2、4 节；证据：‘名称必填’与‘名称为空也可保存’冲突；影响：无法决定空名称能否保存；建议：确认是否必填后统一相关规则。源文件不修改。”

### 局部修改

输入：“仅把第 2 节按钮‘发送’改为‘提交’，对应图注也改；其他章节、REQ-07 和已批准变更记录保留。”

完整预期变更：“第 2 节按钮文案及对应图注：‘发送’改为‘提交’。其他内容不变。”

实际编辑只替换这两处，不能借机删编号、正式历史或重排全文。

## 仅原型与无截图能力

输入：“只做一个独立 HTML：标题‘素材详情’，按钮‘展开说明’，说明文字‘示例素材’，初始隐藏，点击可展开和收起；展开后按钮改为‘收起说明’，收起后恢复‘展开说明’。不要 PRD。环境没有可用浏览器或截图工具，也不安装。”

预期产物为独立 HTML，完整内容示例（此处是教学代码，不代表已创建文件或执行验证）：

```html
<!doctype html>
<html lang="zh-CN">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>素材详情</title>
<style>
body { margin: 2rem; font: 1rem/1.6 sans-serif; }
button { padding: .5rem 1rem; font: inherit; }
</style>
</head>
<body>
<h1>素材详情</h1>
<button id="toggle" type="button" aria-controls="detail" aria-expanded="false">展开说明</button>
<p id="detail" hidden>示例素材</p>
<script>
const toggle = document.getElementById('toggle');
const detail = document.getElementById('detail');
toggle.addEventListener('click', () => {
  detail.hidden = !detail.hidden;
  toggle.setAttribute('aria-expanded', String(!detail.hidden));
  toggle.textContent = detail.hidden ? '展开说明' : '收起说明';
});
</script>
</body>
</html>
```

预期交付说明：“已提供独立 HTML。视觉验证受限：环境无可用截图能力，未验证浏览器交互、展开／收起状态及目标视口；未提供截图。”

不创建 PRD，不尝试安装，不声称已通过视觉验证。若已知按钮实现错误，应报告未完成，不能只说环境受限。
