# PRD 语言表述规范

目标是直接、自然、准确地说明产品规则，不为消除某个词改变需求。语义保真优先于句式和篇幅；完整案例见 [示例](示例.md)。

## 保真底线

- 改写前后保持对象、位置、条件、取值、时序及否定范围不变。禁止、删除、不可操作和计算限制可原样使用否定句。
- 具体表述必须来自材料。输入未给阈值、来源、触发点或提示文案时，不以“具体化”为由补造；按 [入口](../SKILL.md) 的未知处理规则追问或就地待确认。
- 同步、同时、先后、仅等可能表达业务关系，不能当成套话机械替换。

## 语言建议

1. 直接写规则；没有信息增量的铺垫、自证或总结可删。目的句若解释必要边界则保留。
2. 已有明确字段名、条件或文案时准确使用，不用“合理”“适当”掩盖关键缺口。
3. 冗余动词和无逻辑作用的连接词可精简；删除后含义变了就保留。
4. 并列字段、状态和步骤允许相同句式，方便对照。不以“连续三个等长句”为质量阈值；只有重复妨碍阅读时才调整。
5. 保持正式而自然，少用夸张、抒情或营销话术；不用排比、标点强调代替规则。
6. 同一规则只展开一次，其他位置引用。读者需就近理解时可简短提示，不重复改写整条规则。

## 按语境判断，不逐词禁用

| 原表述 | 可做的精简及边界 |
|---|---|
| 对名称进行校验 | 可改“校验名称”；不能补入未给的长度阈值 |
| 对列表进行展示 | 可改“展示列表”；保留原有展示条件 |
| 确保数据准确 | 有已确认规则则直接写规则；否则指出所需定义，不发明校验方案 |
| 同步更新、统一修改 | 保留真实联动含义；仅在不承载对象和时序信息的空修辞中精简 |
| 此外、同时、值得注意的是 | 无逻辑作用时可删；同时执行等实际约束不能删 |
| 作为、充当、标志着 | 仅在等义时改“是／有”，不能消除角色或状态含义 |
| 合理、适当、相关 | 已知具体条件时明确写出；未知时待确认，不随意填值 |
| 本功能、该系统 | 无信息重复时直称对象；必要指代可以保留 |

## 自检

逐条对照输入核验语义，再读一遍是否顺畅。词表只用于发现可能的空话，不作为自动替换或效果评分工具。无依据的“更具体”不是改进，格式更短也不代表需求更准确。
