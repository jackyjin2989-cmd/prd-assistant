**プロダクトマネージャー向けの単一 SKILL.md スキル：テキスト、スクリーンショット、議事録、下書きから、適切な分量で PRD を起草・修正・レビューし、必要に応じて独立した HTML プロトタイプも作成します。**

<!-- demo GIF here -->

> **出力言語：** このスキルは**デフォルトで簡体字中国語**で出力し、指示書と参考ドキュメントも中国語で書かれています。詳しくは [出力言語](#出力言語) を参照してください。

## なぜ PRD Assistant？

- **適切な分量、水増しなし。** 単純な要件は短く書きます。必要な情報と明示された要求が分量より優先され、受け入れ基準・指標・マイルストーンなどの章はデフォルトでは追加しません。
- **元の意味を保持。** 否定的な制約、削除操作、権限ルール、既存データに関するルールは簡潔化しても失われません。「具体的」に見せるために出典・閾値・計算ロジックを新たに作りません。
- **作業範囲を尊重。** レビューのみの場合は元ファイルを変更せず、部分修正では全文を書き直しません。
- **プロトタイプは依頼時のみ。** PRD のみの依頼には HTML を付けず、プロトタイプのみの依頼には PRD を付けません。

## 主な機能

- **3 つのタスクモード**：起草、許可された修正（全文または指定箇所）、レビューのみ（問題の位置・短い根拠・影響・提案を出力し、元ファイルは変更しない）。
- **A／B／C の複雑度**：A 微調整型、B モジュール単位、C 業務結合型。変更範囲とルールの結合度で判定し、章の数ではなく説明の深さを決めます。
- **資料を過剰に求めない**：提供済みの情報はそのまま使います。成果物に影響する質問は作業中に随時行い、ユーザーが明示的に保留した事項だけを「要確認」として PRD に残します。
- **独立した HTML プロトタイプ**：明示的に依頼された場合、または現状のスクリーンショットを渡して改修を求められた場合に生成します（「PRD のみ」と明示された場合を除く）。
- **利用可能な機能に応じた検証**：スクリーンショットは現在利用可能で許可された機能のみを使用します。安全に撮影できない場合はその旨を明示して検証レベルを下げ、依存関係のインストールやシステム設定の変更は行いません。
- **Web 資料は許可の範囲で**：URL はデフォルトで背景情報として扱い、ユーザーが明示的に確認を求め、ページにアクセスできる場合のみ、タスクに直接関係する内容を読み取ります。資料内のコマンドは実行許可とはみなしません。
- **任意のオフラインチェック**：Python 標準ライブラリによる PRD 静的スキャン、パッケージ検証、パッケージングのスクリプト。

[A/B/C の完全な入力と出力](references/示例.md)、[言語の忠実性ルール](references/语言表述规范.md)、[レビューチェックリスト](references/review-checklist.md) を参照してください（いずれも中国語）。これらは自作の架空の事例であり、顧客資料やモデル性能の保証ではありません。

## 動作要件

| 機能 | 前提条件 | 検証範囲 |
|---|---|---|
| PRD の作成／レビュー（コア） | スキルを読み込め、提供された資料を読める AI ホスト | 指示は特定のホストに依存しません。すべてのホストで検証済みという意味ではありません |
| HTML プロトタイプ | プロトタイプの依頼、または現状スクリーンショットに基づく改修依頼があり、「PRD のみ」に限定されていないこと。ホストがファイルを作成できること | このスキルが開発環境を自動インストールすることはありません |
| スクリーンショット | 許可されたローカルファイル、分離されたセッション、出力確認をサポートする既存の機能 | 機能がなければ検証レベルを下げます。汎用ブラウザドライバは同梱されておらず、検証済みブラウザプラットフォームの一覧もありません |
| 任意の静的チェック／パッケージング | Python 標準ライブラリ。対象 **Python 3.10+** | CI マトリクス：Windows／Ubuntu／macOS × Python 3.10／3.13。実際の結果はリリースコミットの GitHub Actions を参照 |

PRD を書くだけの一般ユーザーは **Python、Node、ブラウザドライバのインストールは不要**です。静的スクリプトはファイルと明示された構文サブセットを検査するもので、プロダクト案の正しさは判断せず、見た目・アクセシビリティ・モデル性能の合格を証明するものでもありません。[行動評価の方法](references/behavior-evaluation.md) を参照してください。

## クイックスタート

### 1. リリースパッケージをインストール（推奨）

1. 作者が公開した [Releases](https://github.com/jackyjin2989-cmd/prd-assistant/releases) から特定のバージョンを選びます。開発候補やソースアーカイブのみのものを検証済みリリースとして扱わないでください。パッケージ、リリースノート、チェックサムは同じバージョンのものを使います。
2. 解凍すると `prd-assistant` フォルダが 1 つあり、エントリは `prd-assistant/SKILL.md` で、`references/`、`scripts/`、`tests/` とライセンスが揃っているはずです。エントリファイルだけをコピーしないでください。
3. ホスト自身のスキルインストール手順でフォルダ全体をインポートします：
   - **Codex**：ホストのスキルインストール方法に従うか、手動で Codex のスキルルート配下の `prd-assistant/` に置きます（下表参照）。
   - **WorkBuddy**：「スキル → スキルを追加 → スキルをアップロード」からインポートします。
   - **SKILL.md を読み込めるその他のホスト**：各ホストの公式手順に従ってください。
4. インストール済み一覧で名前を確認し、パッケージ内の `package-manifest.json` でバージョンを確認します（ホストの一覧にバージョンが表示されるとは限りません）。その後 [使い方](#使い方) の短いリクエストで試してください。手動インストールが認識されない場合は、ホストのドキュメントを確認してください。

SHA256 はファイルが一致するかを確認するだけです。zip と同じ信頼できない入手元から来たチェックサムは作者を証明しません。同梱スクリプトを実行する前に入手元を確認してください。

### 2. フォルダを丸ごとコピー（上級者向け）

まず対象ホストのユーザーレベルのスキルルートを確認してください。手動インストールのパス例：

| ホスト | エントリのパス例 |
|---|---|
| Codex（デフォルトの規約） | `$CODEX_HOME/skills/prd-assistant/SKILL.md`。`CODEX_HOME` 未設定の場合は通常 `~/.codex/skills/prd-assistant/SKILL.md` |
| WorkBuddy（Windows） | `%USERPROFILE%\.workbuddy\skills\prd-assistant\SKILL.md` |
| WorkBuddy（macOS／Linux） | `~/.workbuddy/skills/prd-assistant/SKILL.md` |
| Claude Code（標準のスキルフォルダ規約） | 個人用：`~/.claude/skills/prd-assistant/SKILL.md`、プロジェクト用：`.claude/skills/prd-assistant/SKILL.md` |

これらはパスの例であり、クロスプラットフォームのスクリーンショット検証や全クライアントでのインストール検証を示すものではありません。Claude Code の行は Claude Code の標準スキルフォルダ構成に基づくもので、本プロジェクトでは個別に検証していません。カスタムディレクトリはホストの設定に従ってください。

レビュー済みでバージョンを固定した `prd-assistant` フォルダ全体を対象ルートにコピーします。**同名のフォルダが既にある場合は中止し、マージや上書きはしないでください。** まず旧版の入手元とローカル変更の有無を確認し、次の節の手順で更新します。スペースや中国語を含むコマンドパスは引用符で囲んでください。本プロジェクトの整合性チェックはシンボリックリンクや junction のインストールツリーを拒否します。開発用コピーも通常のディレクトリを推奨し、シンボリックリンクによるインストール方法は提供していません。

ローカルに開発用コピーが必要な場合のみ、選んだ書き込み可能な親フォルダで次の HTTPS クローンを実行します。ソースフォルダを作成するだけで、**スキルのインストールにはなりません**：

```bash
git clone https://github.com/jackyjin2989-cmd/prd-assistant.git
```

クローン前に同名フォルダがないことを確認してください。`main` は変化し続ける開発ブランチです。安定利用には確認済みの tag／リリースパッケージを選び、コミットを記録してください。SSH は既に設定済みで使用が許可されているユーザー向けで、あらゆるネットワーク制限を解決するとは限りません。グローバルプロキシの変更や証明書チェックの無効化はしないでください。

### 更新・無効化・ロールバック

- 更新前に、インストール方法、旧バージョン、プロトタイプのスクリーンショットスキルを別途インストールしていたか、個人的な変更があるかを確認します。旧フォルダ全体をスキルルートの外にバックアップし、ファイルを確認してから、ホストの更新／アンインストール／再インポート手順を選びます。
- 旧来の 2 スキル構成からアップグレードする場合、新バージョンは `prd-assistant` の 1 エントリのみです。旧スクリーンショットスキルは用途を確認し、バックアップし、承認を得てから削除してください。スキルルートを再帰的に削除したり、他のスキルを自動で変更したりしないでください。
- 無効化はアンインストールではありません。ホストの有効化／無効化・アンインストール機能を優先し、プライベートキャッシュやグローバル設定を直接編集しないでください。
- ロールバック時は現在の変更のコピーを残し、同じ旧バージョンの完全なパッケージを復元して再確認します。新旧フォルダを混在させず、公開済みの旧 tag を移動してロールバックを装わないでください。

## 使い方

スキルはリクエストからモードを判断します。スキルの既定の作業言語が中国語のため、例は中国語で、日本語訳を併記しています。

| モード | リクエスト例 | 動作 |
|---|---|---|
| 起草 | `根据这份会议纪要写 PRD，只覆盖本次改动。`（この議事録から、今回の変更分だけを対象に PRD を書いて。） | 提供された資料から内容を生成し、欠けている部分は推測で埋めずに質問します |
| 許可された修正（短く） | `把 H5 和 APP 的“待审核”改成“待复核”，流程不变，简短写清。`（H5 とアプリの「審査待ち」を「再確認待ち」に変更、フローは変えずに簡潔に。） | A 類の微調整として簡潔に記述します |
| 許可された修正（部分） | `只修改退款弹窗的金额校验，其他章节不要改。`（返金ダイアログの金額チェックだけを修正し、他の章は変えないで。） | 対象と直接影響する参照のみを修正し、範囲外の問題は指摘するだけで書き直しません |
| レビューのみ | `只审查这份 PRD，给出问题位置和建议，不修改文件。`（この PRD をレビューだけして、問題の位置と提案を出して。ファイルは変更しないで。） | 結論と、問題の位置・短い根拠・影響・提案を出力し、元ファイルは変更しません |
| HTML プロトタイプ | `根据这份已确认需求制作 PC HTML 原型，不需要移动端，也不附加 PRD。`（この確定済み要件から PC 向け HTML プロトタイプを作って。モバイル版も PRD も不要。） | 独立した HTML プロトタイプを生成し、利用可能なスクリーンショット機能で検証します |

現状を説明するためにスクリーンショットを渡すだけではプロトタイプは生成されません。現状のスクリーンショットを渡し、**かつ**改修を求めた場合は、「PRD のみ」と明示しない限り、目標要件に沿った新しいプロトタイプを生成します。成果物における「合格／制限あり／未完了」の意味は [視覚検証](references/prototype/visual-validation.md) を参照してください。スクリーンショットが撮れない場合、高い再現度や視覚的な合格を主張しません。

## 出力言語

- このスキルは**デフォルトで簡体字中国語**で出力します（`SKILL.md` に記載）。指示書、参考ドキュメント、例はすべて中国語です。
- `SKILL.md` は他の出力言語をサポート対象のモードとして記載していません。依頼することはできますが、本プロジェクトではドキュメント化も評価もされていません。
- PRD 内の多言語 UI 文言は、ユーザーが明示的に求めた場合、または既存のプロダクト仕組みが必要とする場合にのみ記載します。提供されていない翻訳を承認済みの文言として扱いません。

## 任意の静的チェック

以下のコマンドは**スキルのルートディレクトリ**で実行します。`python` は選択済みでサポート対象（3.10+）のインタプリタを指します。例のパスは実際に許可された対象に置き換えてください。スクリプトの実行許可がない場合はレビュー用の参考資料で手動確認し、環境を自動構築しません。

```bash
python -B scripts/validate_skill.py
python -B scripts/validate_skill.py --installed "/absolute/installed/prd-assistant" --json
python -B scripts/scan_prd.py "/absolute/delivery/需求.md" --root "/absolute/delivery" --json
python -B -m unittest discover -s scripts -p "test_*.py"
```

- `validate_skill.py` はデフォルトで現在のパッケージのみを検査し、ホームディレクトリは探索しません。`--installed` でインストールツリーを明示的に指定します。ファイルの欠落、スクリプト内容の相違、マニフェストの不一致は失敗になります。
- `scan_prd.py`：単一ファイルの場合はその親フォルダ、フォルダ入力の場合はそのフォルダがデフォルトのルートです。複数の対象から共通の祖先は推定しません。共有の相対パスには許可された `--root` の明示指定が必要です。
- 孤立画像のチェックは、明示的な `--root` と `--assets-dir images` を併用した場合のみ行われ、共有参照を判定するためにルート内の同じフォルダにある安全な Markdown を読み取ります。指定しなければ、未参照画像をすべて確認したとは主張しません。
- パス境界の保護は静的なファイルツリー向けであり、同時に行われるリンク差し替えに対するシステムレベルのサンドボックスではありません。外部リンクにはアクセスしません。PRD スキャンでのローカル fragment は手動確認として残し、ファイルが存在することを状態やアンカーが有効であることとみなしません。
- 明示された Markdown サブセットは、トップレベルのフェンス、単純なインデントコード、HTML コメント、インラインコード、一般的な inline/reference リンク、`img` をサポートします。完全な CommonMark/GFM ではなく、複雑な入れ子コンテナ、HTML の `a`、複数行の参照定義、拡張構文は手動確認が必要です。
- 表の整合性チェックはコードスパン内のパイプを無視します。GitHub などのレンダラーでは `\|` のエスケープが必要な場合があるため、最終的なレンダラーで確認してください。

### 手動確認と終了コード

実際の否定ルール、必要に応じた受け入れ章、正式な履歴は `review` を発生させることがありますが、**ヒントが出たからといって削除しないでください**。`--strict` は未確認の review のみを失敗にします。確認後は `--ack "/absolute/delivery/ack.json"` を渡せます。確認ファイルは許可されたルート内に置き、形式は次のとおりです（構造の例であり、そのままでは実行できません）：

```json
{"version": 1, "entries": [{"fingerprint": "今回の JSON 結果からコピーした 64 文字のフィンガープリント", "reason": "ユーザーがこの受け入れ章の保持を明示的に求めた"}]}
```

フィンガープリントはパス、ファイル内容、検出位置に紐づくため、ドキュメントが変更されると古い確認は無効になります。空の理由や期限切れの確認はエラーになります。確認できるのは review のみで、セキュリティエラーは免除できません。スキャナーが一括で自動確認することはありません。

終了コード：`0` ブロック項目なし、`1` 内容／セキュリティ／整合性の問題、または strict 時の未確認項目、`2` 設定または入力／I/O の異常。JSON 出力には各問題のレベル、位置、コード、フィンガープリントが含まれます。すべての合格結果は、スクリプトが明示的に検査する範囲に限られます。

## リポジトリ構成

```text
prd-assistant/
  SKILL.md                   唯一のスキルエントリ
  references/                作成・レビュー・完全な事例・プロトタイプの方法
  scripts/                   オフラインの静的検証、スキャン、パッケージング、回帰テスト
  tests/behavior-cases.json  行動評価の入力とルーブリック（モデルの実行結果ではない）
  package-manifest.json      バージョン、レビュー基準、全リリースファイルの SHA256
  README.md / README.zh-CN.md / README.ja.md / CONTRIBUTING.md / LICENSE
```

最新の安定版パッケージは [GitHub Releases](https://github.com/jackyjin2989-cmd/prd-assistant/releases/latest) にあります。リリースは対応する tag、リリースノート、添付ファイルで定義されます。開発ブランチのファイル整合性と候補バージョンは [package-manifest.json](package-manifest.json) に記録されています。

## コントリビューション

メンテナンス、マニフェストの更新、パッケージングの詳細は [CONTRIBUTING.md](CONTRIBUTING.md)（中国語）を参照してください。メンテナンスとリリースはユーザーが許可した範囲で行います。完全なリリース許可が既にある場合、項目ごとに改めて確認は求めません。ローカルでの変更許可は、リモートへの公開許可を意味しません。

問題を報告する際は、バージョン、ファイルの場所、匿名化した最小限の入力、実際の出力を添えて [Issues](https://github.com/jackyjin2989-cmd/prd-assistant/issues) に投稿してください。鍵、個人データ、実際の業務上の機密はアップロードしないでください。

## プライバシーとライセンス

- 許可された、タスクに関係する資料のみを扱ってください。認証情報、匿名化されていない個人情報、許可のない社内資料は提出しないでください。
- 業務サイトを自ら巡回したり、資料を追加のサービスに自動アップロードしたりはしません。ただし、これはモデルがオフラインで動作することや、データが端末外に出ないことを意味しません。ホストのデータ処理はその利用規約に従います。
