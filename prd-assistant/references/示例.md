# PRD 示例

展示 A/B 类的目标形态和常见写坏的方式。示例内容为虚构业务，只看结构和写法。

## A 类完整示例

一个改文案 + 改校验的微调需求，全文如下，没有更多章节：

```markdown
# 提现页文案与限额调整

## 改动点

1. **提现页金额输入框下方提示**：「单笔最低提现 100 元」改为「单笔最低提现 50 元，最高 50,000 元」。
2. **提现金额校验**：最低限额由 100 元调整为 50 元；新增单笔上限 50,000 元，超出时输入框下方提示「单笔提现不能超过 50,000 元」，提现按钮置灰。
3. **影响说明**：限额规则同步生效于 H5 和 APP；已发起的在途提现单不受影响。
```

要点：没有背景（不言自明）、没有目标、没有验收、没有总结。三条改动各自写清位置、内容和结果。

## A 类反例（同一需求写坏的样子）

```markdown
## 一、需求背景
随着业务的不断发展，为了进一步提升用户体验，优化提现流程……（三行铺垫）
## 二、需求目标
通过调整提现限额，降低用户操作门槛，提升提现成功率……（凑数指标）
## 三、改动点
（正文与上面相同）
## 四、本期不做
- 不调整提现手续费
- 不调整到账时效
## 五、验收标准
1. 输入 49 元时提示……（把改动点换个说法再写一遍）
## 六、总结
本次需求覆盖了提现页的文案与校验调整……
```

问题：背景目标凑字数、"本期不做"列了没人问的事、验收把规则重复一遍、总结自证。全部应删。

## B 类结构示例（节选）

B 类的骨架：范围表 + 按模块展开 + 表格承载规则。节选自一个虚构的"订单退款拆分"需求：

```markdown
# 订单退款拆分 PRD

## 背景与目标

当前整单退款不支持按商品部分退款，客服只能线下登记，本期支持按商品行发起部分退款。

## 本期范围说明

| 模块 | 本期新增或调整内容 |
|---|---|
| APP 订单详情 | 「申请退款」支持按商品行勾选，展示可退金额 |
| 中台退款审核 | 列表新增「退款类型」列；详情展示商品行明细 |
| 中台退款单导出 | 导出文件同位置增加「退款类型」字段 |

## 功能详细说明

### 1.1 APP 订单详情 · 申请退款

| 调整项 | 规则 |
|---|---|
| 商品行勾选 | 默认全不选；已全额退款的商品行置灰不可选 |
| 可退金额 | 按商品行实付金额减去已退金额实时计算；为 0 时该行置灰 |
| 提交校验 | 未勾选任何商品行时提交按钮置灰 |

### 1.2 中台退款审核列表

「退款金额」列后新增「退款类型」列，枚举：整单退款 / 部分退款。存量退款单显示「整单退款」。

## 历史数据处理

存量退款单不回填商品行明细，详情页明细区展示「历史退款单暂无商品明细」。
```

要点：范围表让评审一眼看清动了哪些系统；规则全部用表格，一行一条可执行；存量数据单独一节交代显示口径。

## AI 味对照

| 写坏 | 写对 |
|---|---|
| 为了提升运营效率，系统将对相关字段进行同步更新 | 保存后，产品库同步更新该字段 |
| 该功能作为本次优化的核心亮点，不仅提升了体验，更保障了准确性 | （删除，直接写规则） |

| 对提现金额进行合理性校验，确保数据准确 | 提现金额低于 50 元或高于 50,000 元时不允许提交 |
