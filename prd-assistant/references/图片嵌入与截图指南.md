# 图片嵌入与截图指南（GitLab / GitHub 图文预览）

本指南将「原型生成与自动截图 → 写入 PRD → Git 平台直接预览」的流程并入 PRD 写作。适用于：需求文档需要配图、用户以截图或设计稿描述改动、或 PRD 需要推到 GitLab / GitHub 分支上供团队预览。

## 写作前的确认项（并入背景提问）

- 参考素材：用户提供的截图、设计稿、原型图、旧页面截图；技能据此生成 HTML 原型，无需用户提供原型文件
- PRD 文件：本次输出的 .md 文件路径
- 截图输出目录：相对 PRD 的图片目录，例如 images/ 或 图片和附件/
- 截图脚本：没有时新建，例如 scripts/capture_prd_screenshots.py
- 同步目标：远程仓库本地克隆路径、分支名、需推送的文件清单
- 视口尺寸：例如 1440x900
- 截图清单：模块、页签、弹窗列表，含触发步骤与 CSS 选择器

## 原型分流与模糊截图

- 仅需说明现有页面或标注改动点时，直接使用截图，不额外生成原型。
- 需要展示改动后效果、状态切换、弹窗、完整流程或 PC/H5 响应式行为时，调用 `html-prototype`。
- 截图模糊时，只提取可辨识的布局与交互线索，无法辨识的文字、数据和规则标为待确认，不放大猜测。
- 若模糊截图来自网站且必须补足信息，先取得用户对目标网站和页面范围的明确授权；由用户在浏览器中自行完成登录、验证码或多因素认证，代理只在授权会话中观察完成任务所需的页面。
- 不索取或保存密码、Cookie、令牌；观察前后遮蔽个人信息、组织信息、订单号和内部地址，不把登录态或真实数据写入原型。

## 原型生成（先还原，再实现改动）

- 分析参考截图：布局结构、组件、样式、颜色、字体、间距、交互状态
- 明确用户描述的改动：加字段、调顺序、加页面、改交互、改文案
- 用 HTML/CSS/JS 生成高保真带交互的原型：支持页签切换、弹窗、hover、表单输入、状态切换等，避免截图空白态
- 原型覆盖 PRD 每个主要模块、页签、弹窗，一个改动对应一个可截图的呈现
- 用户提供的是原页面截图时，原型展示改动后的效果；需要对比时输出改动前后对照

## 嵌入格式（平台能渲染图片的关键）

- 使用 Markdown：`![图片简述](相对路径/文件名.png)`
- 路径相对 PRD 所在目录；禁止本机绝对路径
- 最终 PRD 不得残留「截图占位」「待补图」等纯文字占位
- 引用路径与磁盘文件一一对应，不得裂图
- 文件名含空格或特殊字符时使用 URL 编码，例如 图片和附件/image%201.png

## 截图放置

- 每个主要模块或关键弹窗，在 PRD 对应章节正文后嵌入
- 命名建议：序号-模块名.png
- 弹窗须先打开再截取目标元素，不要截空白态
- PRD 末尾或独立章节维护「截图索引」列表

## 自动截图脚本（对生成的 HTML 原型执行）

- Selenium + Chrome headless（或等价方案）
- 用本地 file URI 打开原型
- 按清单：切换页签 → 打开弹窗 → 截取指定选择器 → 关闭弹窗
- 输出到约定图片目录，允许覆盖同名文件
- 原型 DOM 或交互变更后，同步更新脚本中的选择器与步骤

## 远程同步

- 只同步交付物：PRD、原型、图片目录
- 不同步测试代码、脚本源码、本机配置（除非团队另有约定）
- 有自动 Hook 则依赖 Hook；否则提供并执行手动同步命令
- 成功标准：远程分支上打开 PRD，图片可预览、无裂图

## 执行步骤

1. 确认上方变量与截图清单
2. 根据参考截图与用户描述的改动，生成高保真带交互的 HTML 原型
3. 编写或更新截图脚本并运行，对原型每个模块、页签、弹窗截图
4. 在 PRD 各模块写入或替换为相对路径图片，删除占位文案
5. 更新截图索引
6. 校验：每个引用文件存在，无绝对路径，无占位残留；可选跑项目内一致性测试
7. 同步到远程并回报结果

## 验收

- 图片目录齐全，文件名与 PRD 引用一致
- PRD 全部用相对路径嵌入，无占位残留
- 原型与参考截图高保真一致，改动点与用户描述一致
- 本地预览正常
- 远程 PRD 打开可直接看到截图

## 约束

- 不写死与本任务无关的仓库细节
- 不把密钥、绝对路径写进 PRD
- 不向用户索要 HTML 原型，原型由技能根据参考素材生成
- 说明用简体中文
