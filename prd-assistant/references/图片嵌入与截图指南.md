# 图片嵌入与截图指南

本指南只约束 PRD 中图片的选择、命名、脱敏、引用与排布。HTML 原型的实现、交互与响应式验证、截图对比等事项统一由 [prototype/generation.md](prototype/generation.md) 定义；自动截图只在交付原型且用户明确要求时按需执行，不在本指南维护独立脚本 SOP。仓库或远程同步遵循当前任务和仓库约定，不属于图片写作规范。

## 图片选择

- 优先使用用户提供、项目自有或已获授权的截图、设计稿与原型图。
- 图片应直接支持相邻需求说明；无信息增量的装饰图、重复图和与当前版本不一致的旧图不纳入 PRD。
- 截图模糊时只采用可辨识内容；无法辨识的文案、数据和规则标为待确认，不放大猜测。
- 需要制作或验证 HTML 原型时按 [prototype/generation.md](prototype/generation.md) 执行，不要在 PRD 写作流程中默认生成原型或截图。

## 命名

- 文件名应稳定、可读并能识别页面或状态，建议使用 `序号-模块-状态.png`，例如 `01-订单列表-空状态.png`。
- 同一文档内保持统一命名风格；避免无语义名称、临时名称和重复文件名。
- 尽量不使用空格及特殊字符；已有文件名无法调整时，在 Markdown 路径中正确进行 URL 编码。

## 脱敏

- 嵌入前遮蔽或替换姓名、手机号、邮箱、证件号、账号、组织信息、订单号、内部地址及其他敏感数据。
- 不保留密码、验证码、Cookie、令牌、登录态或可用于还原真实用户身份的信息。
- 脱敏后仍应保留理解需求所需的布局、字段类型和状态关系。

## 相对路径与存在性

- 使用 Markdown 图片语法：`![图片简述](相对路径/文件名.png)`。
- 路径必须相对 PRD 所在目录，禁止本机绝对路径、`file://` 地址和仓库外路径。
- 图片替代文本应简洁描述页面、模块或状态，不能留空。
- 每个引用路径必须对应实际存在的文件，文件名大小写与扩展名保持一致，避免裂图。
- 最终文档不得残留“截图占位”“待补图”等纯文字占位。

## 图片排布

- 每张截图必须紧跟对应描述或对应小标题，让读者无需跨段查找其含义。
- 禁止把各模块截图统一堆到章节末尾或文档末尾。
- 一段说明涉及多张状态图时，分别放在各自状态说明之后，并用明确的替代文本区分。
- 图片与正文的先后关系应在 GitHub、GitLab 等常见 Markdown 预览中保持清晰。

## 交付前检查

- 图片来源合规且内容与当前需求一致。
- 文件命名清晰、统一，无临时文件名。
- 敏感信息已脱敏。
- 所有引用均为仓库内相对路径，且目标文件存在。
- 每张截图紧跟对应描述或小标题，没有统一堆放到章节末尾。
- 无图片占位、无裂图、无本机绝对路径。
