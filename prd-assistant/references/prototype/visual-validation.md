# 截图对比验证

## 可复现环境

记录浏览器、视口宽高、设备像素比、缩放、语言、主题、页面路径和数据状态。关闭动画，固定时间与随机内容，等待字体和图片完成加载。

## 参考矩阵

以下尺寸和状态仅作为参考，实际视口和状态按用户要求、验收需要或已有基准图确定。只检查纳入本次范围的平台、视口和状态。

| 类型 | 参考视口 | 可选状态 |
|---|---:|---|
| PC | 1440×900、1280×720 | 默认、弹层或提交结果、空/错误态、键盘焦点 |
| H5 | 390×844、360×800 | 默认、导航展开、提交结果、空/错误态、软键盘或长内容 |

## 截图驱动的最低验证

截图驱动原型的场景和材料授权边界以 [../input-intake.md](../input-intake.md) 的“截图和设计稿”为准。进入该流程后，按环境能力完成以下验证：

1. 环境支持渲染和截图时，生成当前图并与目标视觉参考至少并排比较一轮；发现影响页面身份、骨架、组件、排版或可用性的差异时，修正后再复查。
2. 环境支持渲染但不能截图时，在目标视口完成至少一轮人工视觉检查。
3. 环境不能渲染时，视觉验证结论记为“未完成”，说明原因和影响，不得宣称高还原、已复刻或视觉验收通过。

检查前先确认输入截图是否完整、是否被裁切、是否包含浏览器外壳或聊天界面等非目标内容。只比较用户要求还原的页面区域；截图无法确定的区域不纳入一致性结论。此要求只适用于截图驱动原型，不把所有普通原型升级为像素级验收。

## 比对顺序

1. 页面是否为正确路由、端类型、视口与状态。
2. 产品身份是否一致：后台/前台类型、设计体系、密度和整体视觉语言不能跑偏。
3. 主容器、顶栏、侧栏、标签页、筛选区、内容列和浮层的几何关系。
4. 表格、表单、按钮、操作列、分页和抽屉等关键组件的形态与尺寸。
5. 标题、正文、按钮和提示信息的视觉层级。
6. 字号、行高、间距、边框、圆角、阴影和颜色。
7. 焦点、悬停、禁用、错误与成功反馈。

每轮只优先修复最高层级的问题：先骨架，再几何与密度，再组件，再排版颜色，最后装饰。只要页面身份或骨架明显不一致，就不得把调整图标、阴影或动画视为有效修复。

## 判定

像素差异只做信号，不单独决定通过。抗锯齿、字体渲染和阴影可能产生噪声；关键控件缺失、遮挡、换行错误或流程不可达即使像素差低也应失败。

截图驱动原型出现以下任一情况，应判定视觉未通过并继续修正：

- 产品类型或设计语言明显跑偏，例如目标是高密度传统后台，却实现成大卡片、大圆角的通用后台；
- 顶栏、侧栏、标签页、筛选区、表格或抽屉等主要区域缺失、顺序错误或比例明显错误；
- 关键组件类型错误，例如侧边抽屉改成居中弹窗、表格改成卡片列表；
- 内容密度明显不符，导致相同视口下行数、列数或留白差异过大；
- 使用浏览器默认控件或无关组件库默认主题，未匹配截图中的可见组件特征。

若受字体、受限制资产、截图裁切或无法渲染等条件限制，应在交付中列出具体差异和未验证项，不得使用“高还原”“已复刻”等确定性表述。

## 验证结论

- **通过**：目标视口已检查，页面身份、骨架、关键组件、排版和核心交互没有阻断性差异。
- **受限**：已完成可执行的检查，但字体、合法资产替代、动态内容或截图缺口仍造成已知差异；列出影响范围。
- **未完成**：环境无法渲染，或缺少决定骨架与关键交互的目标信息；说明阻塞原因和下一步。

## 记录格式

“差异图”和“像素差异”仅适用于自动差异或基准回归，人工并排比较时可填“未执行”。截图驱动原型至少保留以下摘要：

```text
页面/状态：
目标视口：
目标视觉参考：
当前图：已生成 / 未生成
比较方式：人工并排 / 目标视口检查 / 自动差异 / 基准回归
骨架与几何：通过 / 失败 / 未验证
组件与密度：通过 / 失败 / 未验证
排版与颜色：通过 / 失败 / 未验证
交互与状态：通过 / 失败 / 未验证
差异图：按需
像素差异：按需
主要差异：
本轮修正：
剩余限制：
最终结论：通过 / 受限 / 未完成
```

只有项目自有、用户原创或已获授权的材料可作为逐像素基准。第三方页面或来源不明材料仅用于结构、层级、组件模式和视觉语言参考，不作为逐像素复制目标。
