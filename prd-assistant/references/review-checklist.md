# PRD 审校清单

先判断需求类型，再检查核心产品信息是否足以评审。不要用模板章节数量衡量质量，也不要因缺少技术方案、验收标准或原型而判定 PRD 不完整。

## 一、篇幅与边界

- A 类是否半页以内、只有改动点（和必要的一句话背景）。
- 是否出现了用户未要求的验收标准、本期不做、成功指标、里程碑、FAQ、总结段（[写法指南.md](写法指南.md) "按需内容"表允许的情形除外）。
- 是否围绕本次核心功能和改动，没有无关扩写。
- 产品可见异常是否只说明触发条件、反馈和用户下一步，没有推导内部实现。

## 二、通用检查

1. 每条改动是否写清位置、条件、行为、规则和结果。
2. 角色、页面、字段、操作、状态是否只覆盖实际涉及的部分。
3. 枚举、默认值、必填、展示条件和校验文案是否明确。
4. 用户可见异常是否有明确反馈和可继续路径。
5. 存量数据是否只在受影响时说明处理规则。
6. 同一规则是否只定义一次，没有跨章节重复或口径漂移。
7. 术语是否统一，语句是否直接、自然、无套话（对照 [语言表述规范.md](语言表述规范.md)）。
8. 核心分歧是否已集中追问；非关键待确认是否只是标注而没有展开讨论过程。

## 三、按类型检查

### A 微调型

- 文案改动是否给出位置和最终文案。
- 字段改动是否写清取值、默认值、必填、展示和校验。
- 是否没有版本信息、名词解释、流程图等注水内容。

### B 模块级

- 功能入口和适用角色是否明确。
- 页面、字段、操作、关键状态和业务规则是否闭环。
- 用户操作前后的可见结果是否明确。

### C 跨产品复杂业务

- 核心业务流程、共同角色和状态口径是否明确。
- 各产品端的入口、展示、操作和结果是否互相一致。
- 跨端规则是否集中定义，没有重复复制。

## 四、原型与图片（有原型交付时）

- 是否只在满足 `SKILL.md` "原型分流"条件时生成了原型。
- 截图驱动原型是否先识别界面身份、骨架、组件形态、密度和视觉令牌，未擅自改成通用模板。
- 视觉验证是否按 [prototype/visual-validation.md](prototype/visual-validation.md) 的能力判定执行或降级，结论为一句话的"通过 / 受限 / 未完成"。
- 结论非"通过"时，是否避免了"高还原""已复刻"等表述。
- 图片路径为相对路径且文件存在，无裂图和占位。

## 五、编辑残留与最终交付

- 是否删除删除线、草稿标记、占位文字、批注式说明及"XX问题已判断/已解决"等分析过程字样。
- 被否方案是否未以"无 X""非 X 版""已去掉 X"等方式重新出现。
- 正文是否不含 REQ/RULE/AC 编号和追踪矩阵。
- PRD 与原型是否为独立文件。

## 六、审校输出

1. **结论**：可评审 / 补充后可评审 / 核心方案待确认。
2. **关键缺口**：只列影响核心功能的问题。
3. **重复与矛盾**：指出位置并给统一口径。

不要把默认不要求的验收、技术、发布、运营或原型内容列为缺口。
