# 最终交付清理

解决"此地无银三百两"问题：方案已经改对，PRD 里却把讨论中淘汰过的内容又写了回来，用"无 X""非 X 版""已去掉 X"等标签引起读者对已否决方案的关注。

核心原则：**从最终采用的状态重写正文，被否方案当作不存在。**

## 判断规则

对每处内容问一句：没有参与过这轮对话的读者，需要这条信息吗？

**不保留：**

- 只在聊天中讨论过、从未采纳的方案
- 用户纠正过的标题框架、语气和自证句
- 用近义改写、括号、"无 X""非 X 版""已清理"等标签保留的被否内容
- "本期不做/范围排除"——默认不写；仅用户明确要求，或不写会导致读者误解边界时一句话列出，不解释否决原因
- "XX问题已判断""XX问题已解决"等分析过程字样

**保留：**

- 安全、法律、兼容性等硬约束
- 用户明确要求的方案比较、变更日志或迁移说明
- 已发布能力确实被移除时的迁移说明

## 生成规则

- 标题从最终正文重新生成，不出现被否方案的名称或对比框架。错误：`充值审核流程优化（不含自动审核）`；正确：`充值审核流程优化`。
- 确需写范围排除时只写"本期不涉及 X"，不写"（曾考虑但因 Y 否决）"。
- 交付说明只包含正向结果和验证状态，不复述讨论过程。

## 交付前检查

逐项过一遍：

- [ ] 无"无 X""非 X 版""without X"等合规标签
- [ ] 无解释某方案为何不存在的说明
- [ ] 无删除线、草稿标记、占位文字、会话残留
- [ ] 无分析过程字样
- [ ] 标题、范围和交付说明只描述最终采用方案

检查发现问题就修订后重查一遍；仍有实质性歧义时向用户确认。
