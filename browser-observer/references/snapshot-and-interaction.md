# 快照、引用与交互

## 快照优先

页面理解优先使用可访问性树或结构化快照。截图用于补充视觉、画布、图片、复杂 CSS 和空间关系，不能代替结构化观察。

推荐顺序：

1. 列出并确认目标标签页；
2. 获取页面快照；
3. 从最新快照选择元素；
4. 执行一次会改变页面的操作；
5. 等待页面稳定；
6. 重新快照并验证结果。

## 元素引用生命周期

元素引用只在当前页面状态有效。以下情况可能使引用失效：

- 页面导航、刷新或历史前进后退；
- 点击导致弹窗、抽屉、下拉或新页面；
- AJAX、懒加载、分页、筛选和排序；
- 表单提交、校验反馈和状态更新；
- 动画、权限刷新或组件重新渲染。

发生变化后必须重新快照。遇到“引用不存在”时，不重复点击旧引用，而是重新观察并选择新引用。

## 等待策略

优先等待明确条件：关键文本出现或消失、关键选择器出现、URL 变化、加载标识消失。条件未知时采用短等待：

```text
等待 1 至 3 秒 → 快照 → 检查是否就绪 → 必要时再等待
```

不要默认长时间等待，也不要在页面未稳定时连续点击。

## 动作合并

可合并：

- 打开 → 等待 → 快照；
- 点击 → 等待 → 快照；
- 滚动 → 等待 → 快照。

应拆开：

- 快照结果决定点击哪个元素；
- 点击后需要判断出现哪种页面或状态；
- 表单提交可能改变业务数据；
- 页面出现权限、验证码、确认框或错误。

## 交互覆盖

按任务范围观察：

- 导航与返回；
- Tab、筛选、排序和分页；
- 输入、选择、联动、必填和边界校验；
- 弹窗、抽屉、下拉和提示；
- 加载、空、错误、禁用、成功和权限状态；
- 键盘焦点、触控目标和滚动容器；
- 新标签页、下载和上传，仅在明确授权时执行。

## 复杂页面

- 元素过多时将快照限制到主要内容区、表单或弹层。
- 元素不可见时先滚动到可见区域，再重新快照。
- 动态列表先记录当前条目数量、加载条件和分页方式，再触发加载。
- Canvas、图表或图片中的信息用截图记录；若无结构化数据，不猜测精确值。
- iframe 或封闭组件无法读取时，记录限制并请求用户手动操作或提供材料。

## 只读脚本

只读脚本可用于提取链接、标题、字段、表格或样式，但应满足：

- 不修改 DOM；
- 不触发提交、下载或业务动作；
- 不读取认证存储、隐藏凭据或无关个人数据；
- 输出字段最小化并脱敏；
- 正常交互仍使用浏览器原生操作能力。

## 失败恢复

| 失败 | 恢复步骤 |
|---|---|
| 引用失效 | 重新快照，选择最新引用 |
| 元素未出现 | 检查加载状态，短等待后重新快照 |
| 元素被遮挡 | 关闭已授权的遮挡层，或滚动到可见位置 |
| 点击无变化 | 记录当前状态，检查控制台和网络，再决定是否重试 |
| 页面跳到登录 | 停止并让用户重新登录 |
| 操作引发未知确认 | 不确认，先向用户说明 |
| 页面状态不可复现 | 记录前置条件、账号角色、时间和已有证据 |
