# PC / H5 响应式实现规范

原型必须同时支持 PC 和 H5 两种视口。响应式不是简单的整体缩放，而是针对不同设备的使用场景重新组织内容和交互。

## 设备矩阵

| 设备 | 默认视口 | 补测视口 | 典型场景 |
|------|---------|---------|---------|
| PC 桌面 | 1440 × 900 | 1280 × 720 | 管理后台、数据表格、复杂操作 |
| H5 移动 | 390 × 844 | 360 × 800 | 手机浏览器、轻量操作、信息浏览 |

用户有明确目标设备时，按用户要求补充更多断点。

## 核心原则

1. **移动端优先**：先考虑小屏怎么展示，再扩展到大屏
2. **内容重排，不是缩放**：字体、间距、布局都要重新适配，不能只做 `transform: scale`
3. **触控优先（H5）**：按钮、链接等可点击元素的触控目标建议不小于 44 × 44 CSS px
4. **业务一致，呈现不同**：PC 和 H5 共享相同的功能 ID、业务状态和数据规则；差异只在呈现方式和操作路径
5. **渐进增强**：核心功能在两个端都可用；PC 端可以有更丰富的操作和信息密度

## 组件适配对照表

| 组件 | PC 端 | H5 端 |
|------|-------|-------|
| 导航 | 顶部导航栏 + 左侧侧栏 | 底部 Tab 栏 或 顶部汉堡菜单 + 抽屉 |
| 表格 | 完整列展示，支持固定表头、列宽调整 | 卡片式列表、横向滚动、或仅展示关键列 |
| 筛选 | 顶部筛选栏，多条件并排 | 折叠筛选面板，或点击后弹出筛选抽屉 |
| 表单 | 左右两列或三列布局，标签在左侧 | 单列布局，标签在上方，输入框全宽 |
| 弹窗 | 居中模态框，固定宽度 | 底部抽屉，或全屏页面 |
| 按钮 | 小尺寸按钮，可并排多个 | 更大的触控区域，主操作按钮靠底部固定 |
| 分页 | 底部页码导航 | 上拉加载更多 / 无限滚动 |
| 搜索 | 顶部搜索框，带高级筛选 | 顶部搜索入口，点击后展开全屏搜索 |
| 数据详情 | 左右分栏，列表 + 详情 | 进入新页面展示详情 |
| 操作菜单 | 行内操作按钮 + 更多下拉 | 长按菜单 或 右滑操作 或 更多按钮弹层 |

## 布局断点策略

### 断点定义

- **大屏（≥ 1024px）**：PC 布局，侧栏展开，多列内容
- **中屏（768 - 1023px）**：平板过渡，侧栏可收起为图标，列数适当减少
- **小屏（< 768px）**：H5 布局，单栏，底部导航，触控优化

断点不是硬性规定，按内容调整。如果某个组件在 800px 就已经放不下了，就在 800px 处切换，不必等到 768px。

### 断点检查清单

每个断点都要检查：

- [ ] 页面是否有横向滚动条（不应该有，除非是表格/卡片的刻意横向滚动）
- [ ] 所有文字是否完整可见，没有被截断或溢出
- [ ] 所有按钮、链接是否可点击，没有被遮挡
- [ ] 表单输入框是否有足够的宽度输入
- [ ] 弹层/抽屉是否适配视口大小
- [ ] 固定定位元素（导航、底部按钮）是否遮挡内容
- [ ] 图片是否按比例缩放，没有变形

## 导航适配

### PC 导航

- 顶部：Logo、全局搜索、用户头像、通知
- 左侧：一级/二级菜单树，可折叠
- 内容区：面包屑 + 页面标题 + 操作区 + 主内容

### H5 导航

- 顶部：返回按钮 + 页面标题 + 右侧操作（最多 2 个图标）
- 底部：3 - 5 个 Tab 导航（首页、列表、发布、消息、我的）
- 侧滑抽屉：承载更多二级菜单或用户信息

**规则**：
- H5 不使用左右分栏的侧栏导航
- 深层页面必须有明确的返回入口
- 底部导航的当前态必须清晰

## 表格适配

表格是 PC 到 H5 最难适配的组件之一。根据表格复杂度选择策略：

### 策略一：横向滚动（简单表格，列数 ≤ 6）

- 表格整体保持横排
- 外层容器允许横向滚动
- 首列固定（可选），方便对照
- 右侧露出一点内容，提示可以滑动

### 策略二：卡片列表（中等复杂度，列数 6 - 12）

- 每一行变成一张卡片
- 卡片内垂直排列字段
- 关键字段（标题、状态、金额）放大突出
- 次要字段缩小或收起
- 操作按钮放在卡片底部或右侧

### 策略三：关键列 + 详情（复杂表格，列数 > 12）

- 列表只展示最核心的 3 - 5 列
- 点击行进入详情页查看完整信息
- 详情页用分组和折叠组织内容

### 策略四：数据可视化（数据密集型表格）

- H5 端用图表展示趋势和概览
- 详细数据放在"查看全部"的次级页面
- 支持筛选和搜索快速定位

## 表单适配

### PC 表单

- 标签 + 输入框水平排列
- 两列或三列布局
- 必填星号在标签前
- 错误提示在输入框下方或右侧

### H5 表单

- 标签 + 输入框垂直排列（标签在上，输入框在下）
- 单列布局，输入框全宽
- 分组标题分隔不同区块
- 提交按钮固定在页面底部
- 错误提示在输入框下方，用图标 + 文字
- 选择器优先使用原生 picker（日期、地区等）

## 弹层适配

### PC 弹层

- 居中模态框
- 固定宽度（如 480px、600px、800px）
- 顶部标题，底部操作按钮
- 点击遮罩或按 ESC 关闭

### H5 弹层

**底部抽屉**（推荐，大多数场景）：
- 从底部滑出
- 高度为内容高度或屏幕 70% - 80%
- 顶部有拖动条和关闭按钮
- 向下滑动可关闭

**全屏页面**（复杂表单或长内容）：
- 占满整个屏幕
- 顶部导航栏带返回按钮
- 底部固定提交按钮

**居中小弹窗**（简单确认或提示）：
- 小尺寸居中弹窗
- 宽度约 80% 屏幕宽度
- 用于确认、警告、简单输入

## 触控优化

H5 端必须考虑手指触控的精度问题：

- 可点击元素的最小触控区域：44 × 44 CSS px
- 按钮之间的间距至少 8px，避免误触
- 图标按钮要有足够的点击热区（可通过 padding 扩大）
- 链接文字不要太小（最小 14px）
- 表单输入框高度至少 44px，方便点中
- 避免 hover 状态作为唯一交互反馈（移动端没有 hover）
- 点击后要有明确的视觉反馈（按下状态、加载状态、结果提示）

## 状态一致性

PC 和 H5 两端必须保持：

- 相同的业务状态值（如订单状态枚举）
- 相同的数据规则（校验、计算逻辑）
- 相同的权限控制（哪些角色能看什么）
- 相同的功能 ID（用于需求追踪和测试）

呈现方式可以不同，但业务本质必须一致。

## 验证方法

### PC 验证

1. 设置视口 1440 × 900
2. 走通主流程
3. 检查所有页面的布局、对齐、间距
4. 验证弹层、下拉、表格等组件
5. 测试键盘可访问性（Tab 键导航）
6. 补测 1280 × 720 窄屏

### H5 验证

1. 设置视口 390 × 844
2. 走通主流程
3. 检查所有页面是否有横向溢出
4. 验证触控目标大小是否足够
5. 检查弹层/抽屉的适配
6. 验证表单输入的易用性
7. 补测 360 × 800 小屏

### 两端对比

- 功能是否一致
- 数据是否一致
- 状态流转是否一致
- 文案是否一致
- 品牌色和风格是否统一

## 实现技术

使用 CSS 媒体查询 + 相对单位：

- 优先使用 `rem` 或 `em` 做字体和间距，方便整体缩放
- 布局使用 Flexbox 和 Grid，天然支持响应式
- 断点使用 `min-width` 从小到大（移动端优先），或 `max-width` 从大到小
- 图片使用 `max-width: 100%` 自适应
- 通过 `.pc-only`、`.h5-only` 类控制元素的显示隐藏
- 不使用 `zoom` 或 `transform: scale()` 做整体响应式
