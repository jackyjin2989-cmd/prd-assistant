# 浏览器页面观察指南

当用户提供的截图模糊、不完整，或者需要了解真实产品的交互行为、响应式布局时，通过浏览器直接访问目标网站观察页面，是比猜测更可靠的方式。

本文档描述如何用浏览器自动化工具安全、高效地观察页面结构，并将观察结果转化为原型素材。

## 适用场景

满足以下任一条件时使用浏览器观察：

- 用户提供的截图模糊、裁切或分辨率不足，无法识别关键文字或布局
- 需要了解交互细节（弹窗、下拉、状态切换、表单验证）
- 需要验证 PC 和 H5 的响应式行为
- 用户明确说"参考 XX 网站"或"照着 YY 页面做"
- 需要确认现有产品的真实行为作为基线

## 前置确认

开始之前，必须先向用户确认以下事项：

1. **授权范围**：可以访问哪些页面？哪些功能可以点击？是否允许提交表单？
2. **登录方式**：是否需要登录？由谁来登录？（默认：用户自行登录）
3. **数据安全**：页面是否包含真实数据？截图是否需要脱敏？
4. **观察深度**：只看静态页面，还是需要点击交互？需要看几个页面？
5. **输出用途**：仅用于理解业务，还是要据此生成原型？

确认不充分时，宁可保守，不要越权。

## 安全红线

- **不索取、不记录、不输出**任何密码、Cookie、令牌、密钥
- 登录操作由**用户自行完成**，包括验证码、多因素认证
- 不提交任何真实业务数据的表单（测试按钮除外，且需用户确认）
- 截图前检查是否包含：真实姓名、头像、邮箱、手机号、身份证、订单号、金额、公司名、内部 URL；如有，先遮蔽或不截该区域
- 不复制受版权限制的源码、图像、字体、商标、图标库
- 参考布局和交互模式，使用原创代码实现，不逐像素抄袭
- 观察结束后关闭浏览器，清除临时会话状态
- 不在终端输出或日志中打印敏感信息

## 观察流程

### 第一步：准备

1. 确认用户已授权目标网站和页面范围
2. 设置浏览器视口：先 PC（1440×900），后 H5（390×844）
3. 如果需要登录，引导用户自行完成：
   - 打开登录页
   - 提示用户"请在浏览器中完成登录，登录后告诉我"
   - 用户确认后，再继续观察

### 第二步：打开页面并获取结构

1. 导航到目标页面，等待加载完成（网络空闲或关键元素出现）
2. 截取完整页面截图（含滚动区域）
3. 获取页面元素快照，记录：
   - 页面标题和 URL
   - 顶部导航/侧栏导航的结构
   - 主要内容区域划分
   - 关键按钮、链接、表单控件
   - 弹层、抽屉、下拉菜单等组件
4. 提取页面文字内容（用于还原文案和字段名）

### 第三步：交互观察

根据授权范围，点击关键元素观察交互行为：

1. **按钮点击**：点击后发生了什么？跳转？弹窗？状态变化？
2. **表单交互**：输入框有什么校验？错误提示什么样？提交后反馈？
3. **下拉/选择器**：有哪些选项？默认值？级联关系？
4. **状态切换**：Tab 切换？筛选条件变化？列表排序？
5. **加载状态**：加载中显示什么？空状态显示什么？错误状态显示什么？

每次交互后：
- 重新获取元素快照
- 截取状态变化后的截图
- 记录交互前后的差异

### 第四步：响应式观察

1. PC 视口（1440×900）：记录布局结构、侧栏、表格展示
2. 中等视口（1280×720）：观察是否有布局调整
3. H5 视口（390×844）：
   - 导航是否变为抽屉或底栏？
   - 表格是否变为卡片或横向滚动？
   - 按钮尺寸是否适配触控？
   - 弹层是否变为底部抽屉？
4. 记录各断点的关键变化点

### 第五步：整理观察结果

输出一份结构化的观察记录，包含：

```
## 页面信息
- 页面名称：
- URL：
- 所属系统/模块：

## 页面结构
- 顶部/侧栏导航：
- 主要内容区域：
- 底部/其他：

## 关键控件
- 按钮：
- 表单字段：
- 表格/列表：
- 弹层/抽屉：

## 交互行为
- 主流程：
- 状态变化：
- 校验与报错：
- 加载/空/错误状态：

## 响应式
- PC 布局：
- H5 布局：
- 关键断点变化：

## 截图清单
- pc-default.png - PC 默认状态
- pc-modal-open.png - PC 弹窗状态
- h5-default.png - H5 默认状态
- h5-drawer.png - H5 抽屉状态
- ...

## 待确认项
- 模糊或无法识别的内容
- 需要进一步点击但未授权的交互
```

## 工具使用要点

### 常用操作

- 打开页面：`open <url>`
- 等待加载：`wait --load networkidle`
- 截取页面：`screenshot`（当前视口）或 `screenshot --full`（整页）
- 获取元素：`snapshot -i`（带交互元素引用）
- 点击元素：`click @eN`（N 为元素编号）
- 填写表单：`fill @eN "内容"`
- 滚动页面：`scroll down 500`
- 获取文本：`get text @eN`
- 设置视口：通过浏览器参数或窗口大小控制

### 元素引用（Refs）

元素引用（`@e1`、`@e2` 等）在页面变化后会失效。每次导航、点击跳转、动态加载后，必须重新获取快照。

### 链式操作

不需要读取中间结果时，可以将多个操作串联执行，提高效率。例如：打开页面 → 等待加载 → 截图。

需要先看元素再操作时（比如先 snapshot 发现元素再点击），必须分两步执行。

### 视口控制

PC 和 H5 需要分别观察。通过调整浏览器窗口尺寸或使用设备模拟功能来切换视口。H5 观察时，除了尺寸，还要注意触控行为和滚动方式。

### 多个页面

如果需要观察多个页面：
1. 从入口页面开始
2. 按用户路径依次访问
3. 每个页面单独记录结构和截图
4. 记录页面之间的跳转关系

## 常见问题

### 页面有验证码或滑块怎么办？

停止操作，让用户手动完成。不要尝试自动识别验证码。

### 页面内容太多，截图很长怎么办？

截整页图 + 关键区域单独截图。整页图用于全局参考，区域截图用于细节还原。

### 有些元素是动态加载的，抓不到怎么办？

等待元素出现（`wait @eN` 或 `wait "#selector"`），或者滚动触发加载后再获取。

### 网站有反爬机制，访问被拦了怎么办？

不强行绕过。告知用户情况，改用用户提供的截图或录屏作为素材。

### 登录态过期了怎么办？

提示用户重新登录，不要尝试自己恢复会话。

## 观察结果如何用于原型

观察完成后，将结果交给原型生成流程：

1. 用观察记录中的页面结构作为原型骨架
2. 用截图作为视觉参考，还原布局、颜色、间距、字体
3. 用交互观察记录实现状态切换和表单行为
4. 用响应式观察记录实现 PC/H5 双端适配
5. 原型完成后，用截图做对比验证

参考的是**结构、模式和行为**，不是原样复制。原型应使用原创代码、占位图标和通用样式，避免侵犯版权。
