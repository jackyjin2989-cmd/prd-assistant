# HTML Prototype

## 目标

交付可直接打开、可交互、可在 PC 与 H5 视口验证的自包含 HTML 原型。原型用于表达产品行为，不伪造生产能力，不携带第三方受限制资产或用户凭据。

## 输入来源与优先级

原型可以从多种输入生成。按以下优先级取用信息：

1. 用户明确需求与品牌约束；
2. 用户提供的截图、线框图和设计稿；
3. 用户授权访问的网站（通过浏览器观察获取页面架构）；
4. 通用界面惯例。

参考网站只用于观察信息层级、布局规律、交互模式和响应式行为。不得复制受版权限制的源码、图像、字体、商标或大段文案；使用原创结构、样式、占位素材和通用图标。

不同输入场景的处理方式见 [../prd-assistant/references/input-intake.md](../prd-assistant/references/input-intake.md)。

## 浏览器观察

当截图模糊、不完整，或用户提供网站 URL 时，通过浏览器直接观察目标页面，获取更准确的结构和交互信息。

**什么时候使用浏览器观察：**

- 用户提供的截图模糊、裁切或分辨率不足
- 需要了解交互细节（弹窗、下拉、状态切换、表单验证）
- 需要验证 PC 和 H5 的响应式行为
- 用户明确说"参考 XX 网站"或"照着 YY 页面做"
- 需要确认现有产品的真实行为作为基线

**安全原则：**

- 仅访问用户明确授权的网站和页面
- 由用户自行完成登录、验证码或多因素认证
- 不索取、不记录、不输出密码、Cookie、令牌或个人数据
- 截图前遮蔽姓名、头像、邮箱、手机号、订单号等信息
- 不能确认授权或许可时，改用用户提供的脱敏截图

浏览器观察的详细操作方法见 [references/browser-observation.md](references/browser-observation.md)。
网站参考的安全与授权规范见 [references/site-reference.md](references/site-reference.md)。

## 原型生成流程

1. **定义设备矩阵**：PC 默认 1440×900，H5 默认 390×844；按用户目标补充断点。
2. **建立页面清单**：列出需要实现的页面、主流程、关键状态与稳定功能 ID。
3. **语义 HTML 先行**：先完成语义结构和键盘可操作性，再完成视觉样式。
4. **状态可验证**：所有关键动作必须产生可见状态变化；避免只弹出 `alert`。
5. **设计变量统一**：用 CSS 变量管理颜色、间距、圆角与排版；不依赖专有设计体系。
6. **响应式适配**：对窄屏调整导航、列数、触控尺寸和固定元素，禁止仅做整体缩放。
7. **离线可用**：在无网络情况下仍可打开核心原型；若必须使用外部资源，提供降级方案。
8. **验证交付**：运行交互、控制台、溢出和截图对比验证。

## PC / H5 响应式

响应式不是整体缩放，而是针对不同设备重新组织内容和交互。详细规范见 [references/responsive-guide.md](references/responsive-guide.md)。

**关键要求：**

- PC：验证 1440×900，并至少补测 1280×720；明确内容最大宽度、侧栏/顶部导航、表格横向策略、弹层尺寸和键盘焦点顺序。
- H5：验证 390×844，并至少补测 360×800；导航改为抽屉或底栏，多列表格改为卡片、横向滚动或关键列优先，触控目标建议不小于 44×44 CSS px。
- 断点不是整体缩放。逐项说明组件如何重排、隐藏、折叠或固定；禁止 PC 宽表直接压缩到不可读。
- PC/H5 共享相同功能 ID 和业务状态；设备差异只改变呈现与操作方式，不擅自改变业务规则。
- 两端分别验证默认、加载、空、错误、禁用、弹层/抽屉和提交结果；存在端能力差异时，在交付记录中明确。

## HTML 约束

- 默认交付单个 HTML，内联必要 CSS/JS。
- 使用 `header/nav/main/section/form/button` 等语义标签。
- 交互控件提供可见焦点、标签和合理的 ARIA 状态。
- 正文对比度与触控区域满足常见可访问性要求。
- 每个需求映射区域使用 `data-feature="feature-id"`。
- 测试所需状态可通过查询参数或明确控件稳定进入，例如 `?state=empty`。
- 不将密钥、账号、内部 URL 或真实个人数据写入前端。

## 截图对比验证

验证不是追求逐像素复制第三方作品，而是确认自有目标稿与实现的一致性。

1. 固定浏览器版本、视口、缩放、字体和页面状态。
2. 分别截取基准图与当前图，文件名包含页面、视口和状态。
3. 同时检查像素差异与语义差异：布局、层级、文案、状态、操作可达性。
4. 先修复结构性问题，再调整间距、字号和颜色。
5. 设置项目自己的阈值；超过阈值时输出差异图并人工复核。
6. PC 与 H5 分开设基准，动态时间、随机数据和动画应固定或遮罩。

详细方法见 [references/visual-validation.md](references/visual-validation.md)。

## 交付清单

- 原型 HTML（可直接打开运行）；
- 如用户要求，提供脱敏后的本地参考图和差异图；
- 验证记录：视口、路径、状态、交互结果、控制台错误、差异结论；
- 已知限制和待确认项。

## 完成标准

- PC/H5 主流程均可完成；
- 页面无明显横向溢出、遮挡或不可点击控件；
- 键盘可访问主要操作；
- 控制台无未处理异常；
- 截图对比已覆盖关键页面与状态；
- 产物不包含敏感信息、公司专用词或第三方受限制内容。
