# HTML Prototype

## 目标

交付可直接打开、可交互、可在 PC 与 H5 视口验证的自包含 HTML 原型。原型用于表达产品行为，不伪造生产能力，不携带第三方受限制资产或用户凭据。

## 职责边界

本 Skill 负责原型的信息架构转译、页面实现、交互状态、响应式适配和视觉验证，不负责访问网站、处理登录或采集页面证据。

| 任务 | 负责 Skill |
|---|---|
| 访问授权网站、观察页面和交互、采集截图与诊断证据 | `browser-observer` |
| 将事实整理为需求、规则、验收和待确认项 | `prd-assistant` |
| 根据需求、截图或观察记录实现并验证 HTML 原型 | `html-prototype` |

用户只要求核实现有页面时，不生成原型；网站 URL 或截图信息不足且最终需要原型时，先调用 `browser-observer`，再将其观察记录作为本 Skill 的输入。

## 输入来源

按以下优先级取用信息：

1. 用户明确需求、已确认业务规则与品牌约束；
2. 已批准的设计稿、线框图和清晰截图；
3. `browser-observer` 输出的结构化观察记录、状态证据与脱敏截图；
4. 通用界面惯例。

不同输入场景的处理方式见 [../prd-assistant/references/input-intake.md](../prd-assistant/references/input-intake.md)。观察材料中已确认事实、推断、待确认项必须分开使用，未验证行为不得直接实现为确定规则。

## 观察记录转译

消费 `browser-observer` 输出时，只提取原型实现所需信息：

- 页面清单、入口、导航和内容层级；
- 组件类型、字段、操作和可见文案；
- 默认、加载、空、错误、禁用、弹层、校验和成功状态；
- PC/H5 的真实布局差异和未验证断点；
- 截图索引、视口、状态与证据来源。

参考网站只用于理解信息层级、布局规律、交互模式和响应式行为。不得复制受版权限制的源码、图像、字体、商标或大段文案；使用原创结构、样式、占位素材和通用图标。详细边界见 [references/site-reference.md](references/site-reference.md)。

## 原型生成流程

1. **确认输入质量**：核对需求、截图和观察记录是否覆盖目标页面与关键状态；缺口标为待确认，不用猜测补齐。
2. **定义设备矩阵**：PC 默认 1440×900，H5 默认 390×844；按用户目标补充断点。
3. **建立页面清单**：列出需要实现的页面、主流程、关键状态与稳定功能 ID。
4. **语义 HTML 先行**：先完成语义结构和键盘可操作性，再完成视觉样式。
5. **状态可验证**：所有关键动作必须产生可见状态变化；避免只弹出 `alert`。
6. **设计变量统一**：用 CSS 变量管理颜色、间距、圆角与排版；不依赖专有设计体系。
7. **响应式适配**：对窄屏调整导航、列数、触控尺寸和固定元素，禁止仅做整体缩放。
8. **离线可用**：在无网络情况下仍可打开核心原型；若必须使用外部资源，提供降级方案。
9. **验证交付**：运行交互、控制台、溢出和截图对比验证。

## PC / H5 响应式

响应式不是整体缩放，而是针对不同设备重新组织内容和交互。详细规范见 [references/responsive-guide.md](references/responsive-guide.md)。

- PC：验证 1440×900，并至少补测 1280×720；明确内容最大宽度、侧栏/顶部导航、表格横向策略、弹层尺寸和键盘焦点顺序。
- H5：验证 390×844，并至少补测 360×800；导航改为抽屉或底栏，多列表格改为卡片、横向滚动或关键列优先，触控目标建议不小于 44×44 CSS px。
- 逐项说明组件如何重排、隐藏、折叠或固定；禁止将 PC 宽表直接压缩到不可读。
- PC/H5 共享相同功能 ID 和业务状态；设备差异只改变呈现与操作方式，不擅自改变业务规则。
- 两端分别验证默认、加载、空、错误、禁用、弹层/抽屉和提交结果；存在端能力差异时，在交付记录中明确。

## HTML 约束

- 默认交付单个 HTML，内联必要 CSS/JS。
- 使用 `header/nav/main/section/form/button` 等语义标签。
- 交互控件提供可见焦点、标签和合理的 ARIA 状态。
- 正文对比度与触控区域满足常见可访问性要求。
- 每个需求映射区域使用 `data-feature="feature-id"`。
- 测试所需状态可通过查询参数或明确控件稳定进入，例如 `?state=empty`。
- 不将密钥、账号、内部 URL 或真实个人数据写入前端。

## 截图对比验证

验证不是追求逐像素复制第三方作品，而是确认自有目标稿与实现的一致性。自动截图只在原型交付且用户明确要求时按需执行；优先使用当前环境已有的浏览器自动化能力，不交付或长期维护独立 Selenium 截图脚本 SOP。

1. 固定浏览器版本、视口、缩放、字体和页面状态。
2. 分别截取基准图与当前图，文件名包含页面、视口和状态。
3. 同时检查像素差异与语义差异：布局、层级、文案、状态、操作可达性。
4. 先修复结构性问题，再调整间距、字号和颜色。
5. 设置项目自己的阈值；超过阈值时输出差异图并人工复核。
6. PC 与 H5 分开设基准，动态时间、随机数据和动画应固定或遮罩。

详细方法见 [references/visual-validation.md](references/visual-validation.md)。

## 交付清单

- 原型 HTML（可直接打开运行）；
- 如用户要求，提供脱敏后的本地参考图和差异图；
- 验证记录：视口、路径、状态、交互结果、控制台错误、差异结论；
- 已知限制、未验证状态和待确认项。

## 完成标准

- PC/H5 主流程均可完成；
- 页面无明显横向溢出、遮挡或不可点击控件；
- 键盘可访问主要操作；
- 控制台无未处理异常；
- 截图对比已覆盖关键页面与状态；
- 观察记录中的未验证项没有被伪装成已确认行为；
- 产物不包含敏感信息、公司专用词或第三方受限制内容。
